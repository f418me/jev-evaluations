# FOMC evaluation details and optional model comparisons

[Back to the overview](../README.md). Run all commands from the project directory.

The evaluation compares model decisions against a supplied expectation baseline and statement text. Reports measure agreement with synthetic scenario targets, response time, and confidence. Market prices and trading returns are outside the scope of this project.

## Data and provenance

The synthetic fixtures were copied from `asentrx-trade-decision-engine`, revision `fa8f07292accb40a128811b390fd1d02701954e6`:

- `app/expectations.json` → `data/baseline.json`.
- `tests/testdata/fomc-sept-2026/*.json` → `data/statements/*.json`.

These are manually constructed scenarios, not verified historical decisions. Fed URLs in the payloads do not establish authenticity and are not downloaded. The baseline is a frozen repository snapshot, not a current market expectation. This project does not modify the source decision engine.

| Case | Decision against expected +25 bp | Guidance against expected hawkish tone | Target |
|---|---|---|---|
| `expected-hike` | +25 bp | In line | `neutral` |
| `surprise-hold` | 0 bp | More dovish | `positive` |
| `hawkish-50bp` | +50 bp | More hawkish | `negative` |
| `dovish-hike` | +25 bp | More dovish | `positive` |
| `preview` | No announced decision | Preview | `abstain` |

Targets in `data/cases.json`, filenames, IDs, and URLs are excluded from model input.

## Structured answers and policy

`Baseline` validates rate-change signs and directions. Original `notes` remain in the fixture but are excluded from Jev input because they contain trading instructions. `build_state()` sends expectations and the subsequent announcement as separate JSON fields. `FOMCJudgments` asks three questions: actual rate change, absolute tone, and guidance relative to expectations. Questions are expressed in field descriptions using the Pydantic AI TypeSafe adapter.

`decide()` computes the rate surprise in Python. A smaller hike or larger cut than expected produces `positive`; a larger hike or smaller cut produces `negative`. Conflicting, mixed, or unknown guidance does not override a rate surprise. If the rate change matches the baseline, more dovish guidance produces `positive`, more hawkish guidance produces `negative`, and in-line or mixed guidance produces `neutral`.

An unknown rate change produces `abstain`. Offered changes range from −100 to +100 bp in 25-bp increments; other changes must return `null`. A rate surprise requires only rate-change confidence. When rates match expectations, both rate and guidance confidence are required; unknown guidance also produces `abstain`. Absolute tone is diagnostic only. Missing, invalid, or low required confidence produces `abstain`.

`--threshold 0.8` is an unvalidated experimental setting. `minimum_field_confidence` is the minimum confidence among required answers, not a probability of profit or the original Asentrx signal-clarity score. Existing trading thresholds cannot be assumed equivalent. Explanations and rate arithmetic are generated by Python, not requested as free text from Jev.

## Custom inputs and integration

```bash
uv run python fomc.py \
  --baseline data/baseline.json \
  --statement /absolute/path/web-monitor-payload.json \
  --output results/custom.json
```

The payload needs a nonempty `content` field. The baseline must match the event and be fixed before publication. This example does not automatically validate publication dates, source authenticity, or expected outcomes for custom statements. For reproducible runs, use a returned versioned model ID through `JEV_MODEL` or `--model` instead of the mutable `typesafe:jev-latest` alias.

This approach could replace extraction/classification in `FEDDecisionAnalyzer`, but it is not a drop-in replacement for the `FEDDecisionImpact`, `IrrelevantFEDContent`, and `FailedFEDAnalysis` union. Integration would need an explicit adapter, handling for abstentions, and evaluation on unseen statements. There is no order execution or trader connection here.

## Jev-only runs

```bash
uv run python compare.py --jev-only
uv run python compare.py --jev-only --case surprise-hold hawkish-50bp dovish-hike --repeat 3
```

`--jev-only` selects Jev entries from `models.json` or the file supplied through `--config`. Other models are not initialized. A configuration without Jev entries is rejected. Five cases with one model and three repeats produce 15 agent runs. Reports default to `results/jev.json` and `.md`; `--output` selects another path.

## Comparing with the original LLM approach

```bash
uv run python compare.py --case surprise-hold
uv run python compare.py --case all --repeat 3
```

`models.json` contains Jev and two configurations each for OpenAI, Groq, and Gemini. Names must be unique. Model IDs are configuration values; availability and access must be checked with the corresponding provider. Add entries such as:

```json
{"name": "My LLM", "kind": "llm", "model": "openai:my-model-id"}
```

Configure credentials in `.env`: `TYPESAFE_API_KEY`, `OPENAI_API_KEY`, `GROQ_API_KEY`, and `GOOGLE_API_KEY` (or `GEMINI_API_KEY`). The `groq:` prefix selects Groq even when its model ID contains `openai/`; `google:` selects the Gemini Developer API. `GOOGLE_API_KEY` takes precedence if both Google key variables are set. Model selection for comparison is independent of `JEV_MODEL`.

Calls are sequential, model order rotates between repeats, and each run starts without conversation history. Five cases, seven models, and three repeats produce 105 agent calls, potentially with additional transport retries. Provider reasoning defaults apply; this is not a comparison under an identical reasoning budget.

Reports show case, repeat, model, decision, target, PASS/FAIL, seconds, and confidence, followed by mean/median timing and decision explanations. JSON includes full answers, provider metadata, requested/resolved model IDs, request counts, configuration, and baseline. Default paths are `results/comparison.json` and `.md`. Existing synthetic reports with the same name are overwritten, so use `--output` to preserve earlier runs.

Timing covers the agent call, network, validation, and retries, but excludes initialization. Failed calls have recorded timings but are excluded from mean/median timing. Missing credentials and model errors are isolated so other participants can finish. Exit code 1 indicates at least one error or target mismatch.

### Interpretation

`llm.py` uses the original three output schemas and the frozen prompt in `data/llm_fed_prompt.txt` from the revision cited above. Its system prompt receives the complete baseline including `notes`; its user input is the statement text alone. The request timeout is 30 seconds. The source Asentrx app and trader are not imported.

The two approaches use different decision rules. Jev prioritizes rate surprises in Python. The original LLM approach includes relevance checks and may classify conflicting signals as neutral. The preview target is therefore `abstain` for Jev and `irrelevant` for the original approach; these results remain distinct in reports.

The original agent decision is reported without the downstream Asentrx trading gate. `--threshold` applies only to Jev. LLM confidence is a self-assessed signal score, whereas Jev confidence concerns required field answers. They are not directly comparable. Offline tests verify output unions, prompt context, error isolation, repetition, and report generation; they do not establish live model quality.

## Amazon Bedrock

The project dependency `pydantic-ai[bedrock,groq,typesafe]` includes Bedrock support. `llm.py` uses Pydantic AI's Bedrock Converse adapter with the same prompt, output schemas, and timing conventions as other LLM providers.

```bash
uv sync --locked
uv run python compare.py --config models.bedrock.json --case dovish-hike
```

The supplied configuration contains Jev, direct OpenAI access, and Bedrock model entries; inspect `models.bedrock.json` for exact IDs. Direct OpenAI calls also need `OPENAI_API_KEY`. The selected Bedrock model must be available to your AWS account in the configured region and support tool calling through Converse.

Configure a region and one authentication method:

```dotenv
AWS_DEFAULT_REGION=eu-north-1
AWS_PROFILE=my-profile
```

For SSO, first run `aws sso login --profile my-profile`. Alternatively, omit `AWS_PROFILE` and set `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`, with `AWS_SESSION_TOKEN` for temporary credentials. A Bedrock API key can be supplied through `AWS_BEARER_TOKEN_BEDROCK`; existing IAM roles can use boto3's credential chain. Credentials belong in `.env` or AWS configuration, never in model JSON.

No region is chosen automatically. Some models require an inference-profile ID rather than a direct model ID. The AWS identity needs appropriate invocation permissions, including `bedrock:InvokeModel` for Converse. `AWS_READ_TIMEOUT=30` and `AWS_CONNECT_TIMEOUT=10` configure transport timeouts; boto3 retries can make the total call longer.

Missing region, credentials, or model access produces an error row for that model while others continue. Tests use the real adapter with simulated Converse responses; they do not confirm live availability or quality in your account.
